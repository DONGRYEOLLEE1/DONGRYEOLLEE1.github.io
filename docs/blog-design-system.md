## 1. 관찰 결과와 수정의 핵심

Alignment 페이지는 모든 제목을 세리프로 통일한 화면이 아니다. 큰 소개 문장에는 세리프를 사용하지만 글 목록 제목, 추천 글 제목, 설명, 날짜는 산세리프와 서로 다른 크기·굵기로 구분한다. 이전 시안은 홈페이지의 큰 소개 문장만 확대 해석해 일반 글 제목과 한국어까지 세리프로 바꿨다. 이번 수정에서는 연구 목록의 정보 위계와 배치를 가져오고, 한영 글꼴은 가독성 좋은 산세리프로 다시 정한다.

아래 수치는 1440×1050 CSS 픽셀 뷰포트에서 계산된 스타일을 확인한 값이다. 스크롤바를 제외한 실제 레이아웃 너비는 1425px였다. 실제 값은 화면 폭에 따라 변하며 모바일 수치로 재사용하지 않는다. 이 페이지는 스크롤 진입 애니메이션을 사용하므로 로드 직후의 낮은 투명도·이동값을 최종 디자인으로 해석하지 않는다.

| 컴포넌트 | 참고 페이지에서 확인한 값 | 해석 |
|---|---|---|
| 큰 소개 문장 H1 | anthropicSerif, 약 40.56px, 400, 행간 약 50.70px, 자간 약 -0.406px | 문장형 소개의 인상에 사용하는 별도 역할 |
| 강조되는 추천 글 H2 | anthropicSans, 약 21.35px, 700, 행간 약 26.69px, 자간 normal | 큰 이미지와 함께 있어도 제목 자체는 과장하지 않음 |
| 일반 목록 글 H3 | anthropicSans, 약 16.35px, 700, 행간 약 21.26px, 자간 normal | 제목의 크기보다 굵기와 그리드로 구별 |
| 팀의 연구 분야 소제목 | anthropicSans, 약 21.35px, 700 | 글 제목과 역할이 다른 설명 영역 |
| 날짜·팀·메타데이터 | 13px, 400, 행간 약 20.02px, 자간 약 +0.13px | 제목과 다른 정보층. 모바일에서도 이 크기를 유지 |
| 글 목록 그리드 | 4열, 열 너비 약 304.25px, 열 간격 16px | 긴 제목의 자연 줄바꿈과 열 정렬이 핵심 |
| 콘텐츠 프레임 | 왼쪽 80px, 가용 너비 약 1265px | 1440px 뷰포트에서의 관찰값이며 고정 비율로 복사하지 않음 |
| 텍스트 선택 | 배경 rgb(94 93 89 / 25%), 글자 #141413 | 선택도 본문 톤 안에서 작동. 크림 배경 위 합성색은 대략 #D3D2CE |

일반 글 카드는 메타데이터 행의 더 보기 제어와 날짜, 정사각 이미지, 산세리프 H3 제목 순서다. 기본 그리드에는 별도의 본문 발췌를 항상 붙이지 않는다. 따라서 ‘작은 제목 + 긴 요약 + 태그 여러 개’가 모든 카드에 반복되는 화면과 다르다. 더 보기 제어는 해당 카드에 붙은 폭 약 320px의 대화상자를 열며, 그 안에서 요약·작은 관계 그래프·선택 글 프리뷰를 제공한다. 열림 상태에서는 제어의 접근 가능한 이름도 바뀐다. 이 공개 화면만으로 내부 온톨로지나 추천 저장소를 사용한다고 결론 내리지는 않는다.

| 모바일 관찰 조건 | 확인한 스타일·배치 | 적용할 해석 |
|---|---|---|
| 뷰포트 390px, 실제 레이아웃 375px | 좌우 32px 안의 글 카드 약 311px, 1열 | 스크롤바와 실제 콘텐츠 너비를 구별해 측정 |
| 큰 소개 문장 | 25px / 400, 행간 32.5px, 자간 -0.25px | 데스크톱 소개 크기를 그대로 축소 없이 사용하지 않음 |
| 일반 카드 제목 | 15px / 700, 행간 19.5px, 자간 normal | 모바일도 굵기 위계를 유지하면서 크기만 조정 |
| 메타데이터 | 13px / 400, 행간 약 20.02px, 자간 +0.13px | 이미 작은 정보를 더 작게 줄이지 않음 |

컴포넌트 흐름은 소개 문장, 큰 미디어, 팀의 연구 방향 설명, 대표 글, 전체 글 그리드로 구분된다. 개인 기술블로그에는 큰 팀 소개 영상과 다중 슬라이드 자동 전환이 필요하지 않다. 짧은 주제 설명, 명시적으로 선정한 대표 글, 전체 글 목록으로 축소한다. 썸네일이나 반복된 빈 커버가 없어도 제목·설명·날짜만으로 글을 고를 수 있어야 한다.

## 2. 우리 블로그의 화면 구조

| 화면·기능 | 수정할 구성 | 적용 이유 |
|---|---|---|
| SCR-01 홈 / H-01~03 | 짧은 소개와 대표 글 1개. 대표 글 제목은 카드보다 크게, 상세 H1보다 작게 표시 | 글 선택이 목적이며 소개문이 첫 화면을 지배하지 않도록 조정 |
| SCR-01 홈 / H-04 | 다른 글은 일정한 제목·설명·메타데이터 순서로 구성 | 문서마다 큰 제목·다른 배지를 반복하지 않음 |
| SCR-02 전체 글 / A-08·A-13 | 넓은 화면은 메타데이터·정사각 이미지·제목 중심의 4열 그리드. 설명형 목록으로 전환 가능. 필터와 결과 수는 별도 도구 행 | 참고 페이지의 간결한 카드와 문제 해결 기록의 풍부한 목록을 구별 |
| SCR-06 주제 상세 / TD-01~04 | 주제명·짧은 정의, 선택적 대표 글, 역할 필터, 연결 글 목록 | Alignment의 주제별 아카이브 역할을 블로그의 개념 탐색에 대응 |
| SCR-03 상세 / D-02~04 | 날짜·유형, H1, 요약·주제의 역할별 크기와 굵기를 구분 | 목록 카드의 굵기를 그대로 상세 제목에 적용하지 않음 |
| SCR-04 관련 글 / R-01~08 | 영역명은 12px/500, 대상 제목은 18px/600, 관계 이유는 13px/400. 정보가 모여도 카드 전체를 볼드 처리하지 않음 | 본문 옆에서 부드럽게 다음 글을 찾도록 유지 |
| 글 카드의 관련 탐색 / A-14·R-01~08 | 카드의 더 보기 제어에서 연결 요약을 확인하는 소형 팝오버. 상세 본문의 관련 탐색과 같은 데이터·이유를 공유 | 기본 그리드에는 정보를 과밀하게 쌓지 않고 필요한 때 확장 |
| SCR-11 검색 / Q-03~06 | 입력은 22px/450, 결과 제목 17px/600, 일치 문맥 13px/400, 유형·날짜 12px/450 | 입력·결과·문맥·상태를 서로 구별 |
| SCR-00 공통 / G-01~04·G-11 | 워드마크, 메뉴, 상태·버튼을 서로 다른 토큰으로 관리 | 하나의 전역 h1/h2 스타일로 모든 제어의 크기가 바뀌지 않게 함 |

그리드의 열 수는 자료량과 너비에 맞춰 바뀐다. 연구 아카이브는 1440px 이상에서 4열, 1120~1439px에서 3열, 768~1119px에서 2열, 767px 이하에서 1열을 사용한다. 데스크톱 열 간격은 16px, 2열에서는 20px다. 기본 카드형은 메타데이터·이미지·제목을 우선하고 발췌·태그를 모두 반복하지 않는다. 검색 결과나 문제 해결 기록의 풍부한 목록형은 제목·일치 문맥·설명을 제공한다. 실제 이미지가 없는 글은 같은 높이의 가짜 그림을 붙이지 않는다. 제목을 3줄로 자른다면 링크의 접근 가능한 이름은 원문 전체를 유지하고 중요한 단어가 부자연스럽게 끊기지 않는지 확인한다.

A-13 보기 전환은 카드형과 목록형을 같은 결과 집합에 적용한다. 연구 필터의 기본은 카드형, 전체 글과 일반 기록의 기본은 목록형이며 명시적인 view 값이 우선한다. 보기만 바꾸면 q·topic·type·sort·page를 유지하고 view=grid/list로 공유한다. 필터 모두 해제는 보기 선택을 바꾸지 않는다. 카드형은 실제 이미지가 있는 글에 정사각 미디어를 쓰고 연구 도표는 contain으로 보존한다. 목록형은 이미지를 생략하고 메타데이터 열과 제목·설명 열로 정리하며 모바일에서는 다시 한 열로 합친다.

A-14 카드 팝오버는 누른 버튼 가까이에 열리되 작은 화면의 바깥으로 잘리지 않게 위치를 바꾼다. 닫기·Escape·바깥 클릭, 열린 상태의 접근 가능한 이름, 닫은 뒤 초점 복귀를 정의한다. 카드 제목은 항상 일반 글 링크로 유지하고 더 보기 버튼과 중첩된 링크를 만들지 않는다. 팝오버의 선택·링크 이동 구분은 상세 화면의 그래프 규칙과 일치시킨다.

## 3. 폰트와 역할별 토큰

새 기본 글꼴은 한글·영문 모두 Pretendard Variable로 정한다. CSS의 font-family 이름은 Pretendard이며, 예전 serif 변수명은 호환 별칭으로만 남아 같은 산세리프를 가리킨다. Georgia·AppleMyungjo 같은 세리프와 운영체제별 명조 fallback을 제목에서 제거한다. 코드와 식별자는 시스템 모노스페이스를 유지한다. Anthropic의 전용 글꼴 파일을 가져와 쓰지 않으며, 우리 글꼴은 공식 배포본·라이선스를 확인해 자체 정적 자산으로 제공한다.

아래는 참고 페이지의 측정값이 아니라 한국어와 긴 영문 기술 제목에 맞춰 목업에 적용한 값이다. 데스크톱은 768px 이상, 모바일은 767px 이하를 뜻한다. 크기, 굵기, 행간, 자간을 컴포넌트 역할에 묶고 화면 폭에 따라 함께 조정한다. 세부 굵기는 변수 글꼴이 실제 로드되는 상태에서 사용하며 브라우저의 가짜 볼딩에 의존하지 않는다.

## 4. 텍스트 선택 색상

기본 화면은 크림색·검정 활자를 유지하고, 드래그한 텍스트에는 차분한 녹색 계열을 제한적으로 적용한다. 강조색을 카드 배경과 모든 메뉴에 반복하지 않으므로 기존의 절제된 화면과 충돌하지 않는다.

| 테마 | 선택 배경 | 선택 글자 | 글자 대비 |
|---|---|---|---|
| 밝게 | #D6EAE4 | #122F29 | 약 11.44:1 |
| 어둡게 | #315E53 | #F4FAF7 | 약 6.95:1 |

선택 스타일은 문서의 ::selection과 입력창·textarea·code·pre 및 코드 안 문법 강조 요소에 적용한다. Firefox 선택 스타일도 같은 색을 사용한다. 포커스 강조는 밝게 #2C6659, 어둡게 #9FCABB이며 선택 배경과 별도 토큰으로 관리한다. 제목에만 다른 선택 색을 설정하거나 선택 영역의 색과 링크 hover 색을 혼용하지 않는다. 일반 문단을 선택할 수 없게 막지 않는다. 선택은 색만 바꾸며 원문·클립보드 내용·강조 구문을 변경하지 않는다.

## 5. 계획서·화면설계서 반영 위치와 검수

| 문서 위치 | 반영할 변경 |
|---|---|
| 계획서 §1·§4 | 전체 제목을 세리프로 복사하던 방향을 폐기. Alignment의 역할별 정보 위계를 참고한다고 명시 |
| 계획서 §7.1·§7.3 | 홈·전체 글·주제 아카이브의 소개/대표 글/글 그리드를 구분 |
| 계획서 §8.1 | 폰트·색상 외에 역할별 크기·굵기·행간·자간과 선택 색 토큰 추가 |
| 화면설계서 §3.2~3.3 | 전역 볼드·명조 사용을 제거하고 컴포넌트별 글자 계약 연결 |
| 화면설계서 H-01~04·A-08·A-13~14·TD-01~04 | 제목·설명·메타데이터의 순서와 그리드·목록 크기 적용 |
| 화면설계서 D-02~10·R-05~06·Q-03~06 | 상세·본문·관계·검색의 글자 위계와 선택 동작 적용 |

검수에서는 한글 장문 제목, 영어 연구 제목, 한영 혼합 제목을 같은 역할에 넣고 375·768·1280·1440px 화면을 확인한다. 글꼴 이름이 CSS에 적혀 있다는 것과 실제 파일이 로드되었다는 것을 구분해 확인한다. font family, size, weight, tracking의 계산값을 대표 요소별로 기록하고, 일반·굵은 글자·한글·라틴 문자가 의도한 글꼴로 출력되는지 확인한다.

텍스트 선택은 밝은·어두운 테마에서 본문과 코드, 입력창을 각각 드래그해 확인한다. 원문 복사가 유지되고, 코드의 선택 글자가 문법 강조색 때문에 읽기 어려워지지 않는지 검토한다. 이미지가 없는 카드와 긴 제목도 정상 배치되어야 하며, 참고 페이지의 애니메이션과 기업용 영상을 가져오지 않아도 같은 정보 위계가 성립해야 한다.

글꼴의 공식 배포·라이선스 기준은 [Pretendard 저장소](https://github.com/orioncactus/pretendard)를 따른다. 대표 글·한글·라틴 글리프가 포함된 자체 호스팅 파일을 사용하고, 글꼴을 부분 집합으로 만들 때는 새 콘텐츠에 필요한 글리프 누락을 빌드 검증에 포함한다.
