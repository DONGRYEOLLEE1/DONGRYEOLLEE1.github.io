# 빌드 시 관련 글 생성 예제

이 디렉터리는 실제 게시글 10편을 사용하는 UI 목업의 개념·관계 데이터와 관련 글 생성기다. 개념과 관계를 파일로 저장한 뒤 배포 전에 관련 글을 계산할 수 있다는 것을 실행 가능한 형태로 보여준다. 현재 113편 전체의 이전이나 본문 자동 추출을 완료한 산출물은 아니다.

## 입력과 출력

| 파일 | 역할 |
|---|---|
| concepts.json | 개념 이름·별칭·상위 개념·추천 기여 여부. about과 applies 관계의 의미도 정의 |
| article-concepts.json | 글별 공개 상태와 검토한 개념·역할. about은 핵심 주제, applies는 적용한 기술 |
| ../data.js | 고정된 목업의 실제 글 제목·설명·본문 발췌·시리즈 순서 |
| build-related.mjs | 입력 검증 후 공개 글 전체 쌍을 다시 비교하는 Node 생성기 |
| related.json | 입력 해시·처리 버전과 글별 추천 대상·점수·관계 이유·근거 |
| related.generated.js | 같은 결과를 브라우저 목업에 연결하는 스크립트. data.js 다음에 로드 |
| verify-related.mjs | 재현성·비공개 제거·잘못된 관계·추천 이유·빈 추천 검증 |

저장소 루트에서 `node docs/preview/knowledge/build-related.mjs`를 실행하면 결과 JSON과 연결 스크립트가 갱신된다. `node docs/preview/knowledge/verify-related.mjs`는 의미 있는 경계 조건을 검사한다. 실행에 외부 패키지·API 키·별도 서버가 필요하지 않다.

## 실제 계산 예

Reranking 글에는 reranking 개념의 about 관계가 있고 책등 인식 글에는 같은 개념의 applies 관계가 있다. 생성기는 두 글을 연결하고 카드에 `적용 사례 · Reranking`을 표시한다. 원문에서 사용한 Cohere와 RapidFuzz·규칙 기반의 차이를 없애거나 같은 모델의 후속 연구라고 설명하지 않는다.

QLoRA 논문 리뷰와 문제 해결 기록도 같은 원리로 연결한다. 검색 시리즈의 이전·다음은 실제 등록된 순서에서만 계산하며 해당 이유를 별도로 기록한다. ThinkingCap과 추론 서버 글은 현재 10편 안에서 공유하는 구체 개념이나 연재 관계가 없어 추천 0개가 나온다. 최신 글이나 임의의 글로 빈 슬롯을 채우지 않는다.

## 계산 계약

| 항목 | 규칙 |
|---|---|
| 후보 | 자신을 제외한 공개 글. 구체 개념을 공유하거나 명시적 시리즈의 이웃인 경우 |
| 개념 역할 | about=1.0, applies=0.8 |
| 희소성 | 공개 글의 문서 빈도로 IDF 계산, 상한 3 |
| 개념 유사도 | 역할과 IDF로 가중한 Jaccard. 넓은 RAG·검색 개념은 추천 점수와 후보 적격성에 기여하지 않음 |
| 최종 점수 | 구체 개념 유사도 0.85 + 시리즈 인접 여부 0.15 |
| 정렬 | 점수 내림차순, 동점은 불변 글 ID. 최대 4개 |
| 관계 이유 | 실제 about·applies·series 관계를 읽고 고정된 템플릿으로 생성 |
| 기존 편집 추천 | data.js의 기존 related는 계산 입력의 인용 관계로 사용하지 않음 |
| 별칭 | 동의어만 등록. GRPO·BM25·MTP·NF4처럼 관련 방법인 용어를 상위 개념의 동의어로 합치지 않음 |
| 상위 개념 | 현재는 빈 배열. 참조와 순환을 검증하지만 조상 확장 점수는 이번 예제에 포함하지 않음 |

이 가중치는 작은 목업을 위한 명시적 시작값이며 측정된 최적값은 아니다. 정식 추천 파이프라인에는 종합 계획서의 보류 평가·기준선 비교·임계값 검증을 적용한다.

## 새 글과 Vercel

새 글의 핵심 개념과 적용 역할을 검토해 입력 파일에 반영한 다음 생성기를 실행하면, 새 글뿐 아니라 모든 기존 공개 글의 추천도 다시 계산된다. 개념을 제안하는 과정에 사전·LLM을 추가할 수 있으며 그 결과를 검토하는 작업과 추천 계산의 자동화를 구분한다. 현재 입력 개념은 사람이 확인한 편집 데이터다.

Vercel에서는 이 명령을 사이트의 빌드 단계에 연결한 뒤 생성된 글별 JSON·HTML을 배포하면 된다. 독자가 글을 여는 시점에는 이미 계산된 연결을 읽으므로 그래프 DB나 LLM을 호출할 필요가 없다. 실시간 편집·관계 질의가 필요해지면 같은 ID와 관계 모델을 외부 DB로 옮길 수 있다. 여러 글을 종합해 질문에 답하는 GraphRAG는 그다음에 별도로 선택할 기능이다.
